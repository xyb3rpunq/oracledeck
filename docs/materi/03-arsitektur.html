Topik 03

Fungsi dan Arsitektur Basis Data Terdistribusi

Empat arsitektur sistem, model struktural DDBS tiga lapis, model ANSI/SPARC, dan arsitektur N-tier.

Kemampuan akhir yang diharapkan. Memahami model arsitektur dan fungsi-fungsi pada BDT dan dapat menerapkannya dalam merancang BDT.

Empat alternatif arsitektur

ArsitekturPenempatanCocok untukKelemahan utama
Stand-aloneDBMS, basis data, dan aplikasi di satu komputerLatihan, apotek kecil, wartel, hotel kecilHanya satu pengguna
TerpusatDBMS dan basis data di satu server, banyak terminalStartup, situs internet, instansi kecilServer mati → seluruh aktivitas berhenti
Client-serverAplikasi di klien, mesin basis data di serverBisnis kecil hingga menengahSkalabilitas terbatas, koneksi terus dijaga, sulit diamankan
TerdistribusiData tersebar di banyak situs, logis satu kesatuanOrganisasi bercabang, lintas kotaKompleksitas dan biaya pengelolaan

Dua jenis transaksi pada sistem terdistribusi

  • Transaksi lokal — hanya mengakses data pada situs tempat transaksi dijalankan
  • Transaksi global — mengakses data pada beberapa situs berbeda

Alasan membangun sistem terdistribusi

  • Data bersama — pengguna di satu situs memakai data yang ada di situs lain, seperti antar cabang bank
  • Ketersediaan — jika satu situs gagal, situs lain melanjutkan operasi sampai selesai
  • Otonomi — tiap situs mengontrol data lokalnya; administrator global bertanggung jawab atas keseluruhan sistem

Karakteristik menurut fungsionalitas

KarakteristikIsi
Multiple processesSetiap proses memiliki thread mandiri, eksplisit maupun implisit
Interprocess communicationProses berkomunikasi lewat pesan; waktu tempuh pesan bergantung media
Disjoint address spacesRuang alamat tiap proses terpisah, fisik maupun virtual

Tiga lapis arsitektur D-DBS

Model datalogical ANSI/SPARC

  • GES (Global External Schema) — rangkaian skema eksternal yang dilihat aplikasi
  • GCS (Global Conceptual Schema) — skema konseptual global, penghubung gambaran pengguna dengan gambaran terdistribusi
  • GIS (Global Internal Schema) — informasi yang dibutuhkan untuk mengakses data terdistribusi dan LDBMS
  • LCS / LIS — skema konseptual dan internal basis data lokal di tiap situs

GCS adalah nexus rancangan: seluruh transparansi distribusi bertumpu padanya. Fragmentasi dan alokasi didefinisikan sebagai pemetaan dari GCS ke LCS.

Arsitektur 3-tier dan N-tier

N-tier adalah bentuk umum dengan tiga komputer atau lebih. Keuntungannya: tiap tingkat dapat berjalan pada prosesor dan sistem operasi yang sesuai, dan dapat diperbarui secara independen dari tingkat lain.

TierKomponenIsi
1Client applicationBerjalan di komputer pengguna; tidak bisa mencapai RDBMS tanpa melewati tier 2
2Application serverBerisi package, objek, method, fungsi, dan aktivitas kueri
3RDBMS applicationKumpulan basis data dan data resource manager

Coba di terminal

Kueri di bawah memperagakan konsep topik ini pada data sungguhan. Tekan ▶ Jalankan untuk membukanya di Terminal SQL, lalu ubah sesuka hati — sesi terminal adalah salinan pribadi di peramban Anda.

Skema eksternal = view

Lapisan eksternal ANSI/SPARC: pengguna bagian keuangan hanya melihat ringkasan biaya. rumahsakit

CREATE VIEW v_keuangan AS
  SELECT d.spesialis, SUM(pd.biaya) AS pendapatan
    FROM dokter d JOIN pasien_dokter pd ON d.id_dokter = pd.id_dokter
   GROUP BY d.spesialis;
SELECT * FROM v_keuangan ORDER BY pendapatan DESC;

Skema konseptual di kamus data

Katalog sistem menyimpan definisi tabel, kolom, dan kendala — lapisan konseptual. rumahsakit

SELECT table_name, column_name, data_type, nullable
  FROM user_tab_columns
 WHERE table_name = 'PASIEN_DOKTER';
